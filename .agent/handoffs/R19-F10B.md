# R19-F10B — reference retry lease and schedule gap

Repairs the second bullet of T19 F-10 (REQ-042, REQ-043).

## Change

- `wagering.Service.RetryPending(ctx, id, owner)` now requires the caller's lease owner. After taking the wallet lock and the transaction row lock, a non-terminal row must be leased to `owner` with an unexpired lease and have `next_attempt_at` due. Otherwise it returns `wagering.ErrClaimNotHeld` before any write: no `attempt_count` increment, no reschedule, no early TTL/attempt-cap rejection, no wallet, ledger or outbox effect.
- The check uses new `pg.Tx.ClaimHeld`, which compares on the database clock (`clock_timestamp()`), the same clock `ClaimTransactions` uses. The service clock (`Service.Now`) still drives backoff and TTL.
- A terminal row is still returned as a replay with no effect. Wallet-then-transaction lock order, crash takeover through lease expiry and the single-transaction apply are unchanged.
- The reference worker passes its owner and reports `ErrClaimNotHeld` as `ResultStale` (info log, not an error). `Retrier` gained the `owner` parameter; package docs updated.

## Tests (live PostgreSQL, separate pools per worker)

- `TestExpiredLeaseOwnerCannotConsumeAttemptBudget`: A's lease expires and B takes over; A's repeated retries change nothing (attempts, schedule, owner, outbox). B spends exactly one attempt, then a late A retry is still refused, and the `MaxAttempts=3` budget is intact (the third attempt rejects).
- `TestEarlyRetryCannotConsumeAttemptBudget`: unleased, leased-but-not-due and wrong-owner retries on a not-due row, with the TTL already passed, leave the row, outbox and wallet untouched.
- `TestTwoWorkersDueValidLeaseResolvesOnce`: concurrent A (lease holder) and B; A resolves once, B has no effect, one ledger entry and one processed event.
- `TestWorkerReportsLostClaimAsStaleWithoutSpendingAttempt`: worker-level stale result, no error.
- Existing `TestStaleClaimDoesNotDoubleApply` and `TestPendingReferenceAndInboxReplay` now claim a due row first.
- Mutation check: disabling the guard makes the expired-lease, early-retry and worker-level tests fail.
