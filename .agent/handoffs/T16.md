DECISIONS / ASSUMPTIONS
- In-process service (real Fx modules and TCP listener) rather than the Compose `app` container, so tests own a scratch database and can assert "no effects" in SQL. Keycloak and PostgreSQL are the shared Compose containers; the shared Compose project is never restarted or reset, and the only shared-state write is a throwaway Keycloak client (per-client access-token lifespan, so other clients/tests are unaffected) removed on cleanup. Admin credentials default to admin/admin (`WAGERING_TEST_KEYCLOAK_ADMIN_USER/_PASSWORD` override).
- Env contract: `WAGERING_TEST_KEYCLOAK_URL` (host URL whose issuer matches `OIDC_ISSUER_URL`, e.g. http://localhost:8082) and `WAGERING_TEST_ADMIN_URL` (same variable the other integration suites use).
- Real expiry is exercised by waiting ~5s (3-4s lifespan), so the matrix and expiry tests take a few seconds each.
- Asserted API contract as implemented by T08: provider routes need provider scope, wallet/ledger/reconciliation need internal scope; foreign-provider lookups answer 404 (not 403); a foreign providerId in the body answers 403; idempotency keys are namespaced per provider.
- SQS is not exercised here (REQ-078 SQS coverage belongs to T15/T17). Health/readiness (T13) is not wired yet, so the matrix does not include those routes; add them as unauthenticated rows when T13 lands.

KNOWN RISKS
- Tests need the Compose Keycloak realm in its R13 state (provider_id, `roles`, audience `account`); an older cached realm makes `idptest.Token` or the claims test fail with a clear message.
- Tests that sleep for token expiry are timing-based; the expiry test skips (not fails) if the IdP answered so slowly that the token expired before the pre-expiry check.
- Nothing here covers token revocation: revoked tokens remain valid until `exp` (documented limitation).
- Pre-existing, not from this task: `gofmt -l` reports `internal/domain/t14_test.go` and `internal/idempotency/t14_test.go`; T19 should format them.
