IMPLEMENTED
F-1 mechanism (verified against MiniStack 1.5.18 source and live):
- MiniStack with `AUTH=true` enforces IAM identity policies and queue resource policies, but only for **named IAM users**. It always treats the access key `test`, an empty/unsigned request, any 12-digit key and its own root key as root, and serves unauthenticated admin endpoints (`/_ministack/reset`, `/_ministack/sqs/messages`, ...). IAM alone therefore cannot enforce the boundary; this was confirmed with a throwaway broker before designing.
- `compose.yaml`: broker (`localstack`) runs with `AUTH=true`, a non-default root key, and is **not published**. A new `sqs-gateway` (nginx, `infra/localstack/gateway.conf`) is the only door (port 4566). It forwards only POSTs signed with an `AKIA...` IAM-user key, rejects credentials in the query string, forwards exactly one validated `Authorization` header, and blocks every `/_*` path except the health probe. MiniStack then enforces the user's policies.
- `infra/localstack/init-sqs.sh`: rewritten without `jq`, `set -euo pipefail`. Creates the three queues (same redrive, `maxReceiveCount=3`), four IAM users with least-privilege policies, and a queue policy on the inbound queue (explicit Deny of `sqs:SendMessage` to everyone except `wagering-producer`, so even an identity granted SendMessage later is blocked). Verifies the applied policy and identity policies before writing the readiness marker. Generated keys are written as AWS shared-credentials profiles to the `broker-credentials` volume.
- Identities: `wagering-producer` (SendMessage inbound only), `wagering-app` (receive/delete/change-visibility on inbound, SendMessage on events), `wagering-broker-operator` (sqs:* on queues for tests/ops; cannot publish inbound because of the queue policy), `wagering-provider-probe` (no queue access; stands in for a provider).
- Fail closed: the `localstack` healthcheck requires `/run/provision/ready` (tmpfs, so a stale marker never survives a restart). The marker is written only after every step succeeds; `app` waits on `sqs-gateway`, which waits on `localstack`. Verified: with the script broken, MiniStack logs `Ready script ... failed (exit 127)`, no marker, container `unhealthy`.
- The app container signs as `wagering-app` via `AWS_SHARED_CREDENTIALS_FILE`/`AWS_PROFILE` (read-only volume); no static root key is in its environment. No production Go code changed.
- `infra/localstack/export-broker-credentials.sh` copies the generated identities to `tmp/broker-credentials` for host-side tests.

DECISIONS / ASSUMPTIONS
- IAM is claimed to work only for the named identities, and only because the gateway removes MiniStack's root bypasses; both were tested against the live Compose broker. I did not claim IAM works for the root/`test` paths: those are blocked by the gateway, not by IAM.
- Chose a gateway over relying on network isolation because tests and developers reach the broker from the host and identity-level evidence was required (producer vs non-producer).
- The operator identity cannot publish to the inbound queue (queue policy) but can read/delete from it; it exists for tests and operations only.
- Custom audience (`included.custom.audience`) instead of a `wagering-api` client: no client object is needed and it avoids `account`.
- `README.md` and `.env.example` were touched only so documented commands keep working; ARCHITECTURE.md and DECISIONS.md were not (T18/doc-owned).

KNOWN RISKS
- Limitation (document in ARCHITECTURE.md, correct D12 wording): MiniStack does not verify SigV4 signatures, so an `AKIA...` key id works as a bearer credential locally. Real SQS verifies signatures and IAM; production needs managed credentials.
- Keys are generated at broker start and change on every broker restart; the app reads them once at startup, so restart the app after restarting `localstack` (`docker compose restart app`), and re-export credentials for host tests.
- Keycloak imports the realm only into an empty database: an existing stack needs `docker compose down -v` before the new audience applies. The old `lead` stack must be recreated (`docker compose down -v && docker compose up -d --build --wait`) before the README commands with default ports work; its broker still accepts `test/test`.
- The nginx gateway adds a hop and a new image (`nginx:1.27-alpine`).
- Flaky system scenario "HTTP SQS crossing, commit-before-delete crash, restart replay" (`tests/system`, `-race`). Measured with 8 runs each: through the gateway 3 failed (all at `multiprocess_test.go:186`, redelivered message not deleted within 20 s); bypassing the gateway (direct to the broker container) 2 failed (at `:167`, fault marker not written). The sample is too small to show the gateway has no effect, so I did not prove or rule out a contribution; both paths flake, and the scenario's timing code was not changed by this task. Without `-race`, `go test -p 1 ./tests/...` passed. Worth a dedicated look (R-task) before relying on `-race ./tests/system` as a gate.
