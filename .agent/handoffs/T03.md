## IMPLEMENTED
Package `wagering/internal/domain`, stdlib only (REQ-004; enforced by `static_test.go`, which also forbids any float type/literal/`strconv.ParseFloat`, REQ-009).
- **Money** (`money.go`): `int64` cents + `Currency` (3 ASCII letters, upper-cased on parse). `ParseMoney(string, Currency)` accepts `digits[.d|.dd]` only; rejects empty, sign, exponent, NaN/Inf, `.5`, `5.`, >2 decimals, separators, whitespace, non-ASCII digits, overflow. `NewMoney` (signed), `Zero`, `Add/Sub/Neg/Cmp/Equal`, `IsZero/IsPositive/IsNegative`, `Amount()` (always two decimals, handles MinInt64), `String()`. Overflow + currency + uninitialized checks on every op. JSON `{"amount":"10.50","currency":"BRL"}`; `UnmarshalJSON` is the strict external parser (string amount, no unknown fields, non-negative). Negative Money marshals but does not unmarshal (internal differences only).
- **Kinds/rules** (`kinds.go`): `Kind` OPENING + BET/WIN/LOSS/REFUND/ROLLBACK, `Status`, `Direction`, `RulesFor(kind)` table (amount rule, reference rule, ledger?, direction, insufficient-funds code), `ParseExternalKind` rejects OPENING, `Status.CanTransitionTo` (REQ-021).
- **Wallet** (`wallet.go`): private fields; `NewWallet` (zero, v1), `RehydrateWallet(WalletState)`, `Credit/Debit` return a `Movement` and bump version; balance never negative; wallet untouched on error. `State()` snapshot.
- **LedgerEntry** (`ledger.go`): `NewLedgerEntry(id, walletID, txID, Movement, now)` / `RehydrateLedgerEntry`; validates positive amount, single currency, after = before ± amount. `CalculateBalance` for reconciliation.
- **WagerTransaction** (`wager_transaction.go`): `NewExternalTransaction(params)` (PENDING; per-kind amount/reference rules; OPENING refused), `NewOpeningTransaction` (PROCESSED, INTERNAL, no external fields), `RehydrateWagerTransaction(state)` re-validates all invariants by status/origin/kind. Transitions `MarkProcessed/MarkRejected/MarkFailed/MarkPendingReference/RecordReferenceAttempt` are atomic (invalid candidate state leaves object untouched). `CheckReplay(hash)` → conflict error.
- **Reference rules** (`reference.go`): pure `EvaluateReference(tx, *Reference)` → Proceed/Wait/Reject with failure code, expiry code and ledger direction. Implements D07/D08/D09 (see DECISIONS).
- **Retry policy** (`retry.go`): `RetryPolicy{BaseDelay, MaxDelay, TTL, MaxAttempts}`, `DefaultRetryPolicy()` = 1s/5m/24h/no attempt cap, `Backoff`, `Exhausted`. Also used for outbox publish backoff.
- **Process** (`process.go`): pure, atomic `Process(ProcessInput)` applying the explicit BET/WIN/LOSS/REFUND/ROLLBACK rules to a locked `*Wallet` + `*WagerTransaction` (+ optional `*Reference`), returning `ProcessResult{Outcome, Movement, Ledger, Events}`. Business rejections are **results, not errors**. The use case (T07) may use it directly or reimplement on top of the lower-level pieces.
- **OpenWallet** (`open_wallet.go`): zero balance → wallet only; positive → wallet(v1 with balance) + OPENING + CREDIT ledger (0→amount) + `WagerTransactionProcessed` + `WalletBalanceChanged` (walletVersion 1).
- **Events** (`events.go`): `Envelope[T]{EventMeta, Data}`; header JSON `eventId,eventType,aggregateId,correlationId,causationId?,occurredAt,version,data`; UTC RFC3339(Nano) timestamps; constructors set type and `EventVersion=1`. Types: `WagerTransactionProcessed`, `WagerTransactionRejected`, `WagerTransactionPendingReference`, `WalletBalanceChanged` (payload per REQ-073: walletId, transactionId, direction, money, balanceBefore, balanceAfter, walletVersion).
- **Outbox** (`outbox.go`): `OutboxEvent` holds an immutable JSON snapshot (copy-on-read), stable eventId, attempts, nextAttemptAt, publishedAt; `IsDue`, `MarkPublished`, `RecordPublishFailure`; rehydrate verifies payload header == stored columns.
- **Inbox** (`inbox.go`): `InboxMessage{consumer, messageId, hash, receivedAt, completedAt}`, `CheckReplay` → `ErrInboxHashConflict`, `Complete`.
- **Errors** (`errors.go`): `*Error{Kind, Code, Message, Cause}` with kinds invalid / rejected / conflict / transient / permanent; `errors.Is` matches Kind+Code; sentinels `ErrInvalidAmount`, `ErrCurrencyMismatch`, `ErrAmountOverflow`, `ErrInvalidTransition`, `ErrHashMismatch`, …; helpers `IsTransient/IsPermanent/IsRejection/IsConflict/IsInvalid`, `Transient(err)`, `Permanent(err)`, `FailureCodeOf(err)`. `FailureCode` constants (stable wire strings): `INSUFFICIENT_FUNDS_BET`, `INSUFFICIENT_FUNDS_REVERSAL`, `REFERENCE_NOT_FOUND`, `REFERENCE_UNRESOLVED`, `REFERENCE_FAILED`, `REFERENCE_MISMATCH`, `ALREADY_REVERSED`, `WALLET_MISMATCH`, `CURRENCY_MISMATCH` (REJECTED) and `PERMANENT_FAILURE` (FAILED).
- `UUID` ([16]byte, canonical lowercase text, `NewUUID`, `ParseUUID`) and `IDGenerator` for deterministic tests.

## DECISIONS / ASSUMPTIONS
(all verifiable against SPEC.md by the Lead; none read by me)
1. IDs: `walletId`, transaction/ledger/event IDs are domain `UUID`. `providerId`, `playerId`, `roundId`, `gameId`, `externalTransactionId`, `idempotencyKey`, reference id are **opaque strings**: non-empty, ≤255 bytes, valid UTF-8, no control chars, no leading/trailing whitespace (never silently trimmed). If SPEC says playerId etc. are UUIDs, T04 should normalize before hashing/passing.
2. Currency is validated by shape (3 letters, upper-cased), not against the ISO 4217 registry.
3. `ParseMoney` accepts `10`, `10.5`, `10.50` (always serialized with two decimals, D06); leading zeros allowed.
4. REFERENCE: BET and LOSS **forbid** `referenceExternalTransactionId`; WIN optional (must be a BET); REFUND/ROLLBACK required. Verify against SPEC (LOSS/BET referencing is the riskiest assumption).
5. `EvaluateReference` order: identity (provider/player/round → `REFERENCE_MISMATCH`, wallet → `WALLET_MISMATCH`, currency → `CURRENCY_MISMATCH`), kind compat, exact amount for REFUND/ROLLBACK (`REFERENCE_MISMATCH`), status (pending → wait, rejected/failed → `REFERENCE_FAILED`), then reversals (`ALREADY_REVERSED`). Missing reference waits and expires as `REFERENCE_NOT_FOUND`; existing-but-pending waits and expires as `REFERENCE_UNRESOLVED`. ROLLBACK of BET credits; of WIN/REFUND debits (`INSUFFICIENT_FUNDS_REVERSAL`).
6. Reversal exclusion (D07): BET allows one successful REFUND-or-ROLLBACK total; WIN/REFUND allow one ROLLBACK. The persistence layer must supply `ReversalState` (from PROCESSED reversals) under the wallet lock; the domain does not see other transactions.
7. Retry: attempt count is 1 on entering PENDING_REFERENCE; `Exhausted(attemptsAfterThisLookup, createdAt, now)`; `MaxAttempts=0` means TTL only. Defaults 1s/5m/24h are starting values; counts must come from config (D08 open item).
8. Events: `aggregateId` = walletId for every event (per-wallet FIFO group, D15). `causationId` = transaction id in `Process`/`OpenWallet`; `correlationId` supplied by caller. Event type names are my defaults (see STATUS). `WagerTransactionPendingReference` is emitted once, on first entry. Order inside a commit: processed, then balance-changed.
9. REJECTED transactions keep the wallet balance observed at rejection (`ResultBalance`, `observedBalance` in the event) except wallet/currency mismatch (unknown/other currency → absent).
10. FAILED always has `PERMANENT_FAILURE`; transient infra errors are `domain.Transient(err)` and never reach a terminal status (REQ-022).
11. OPENING identity: internal origin, random UUID supplied by the generator; uniqueness per wallet must be enforced by the DB (D04); the domain guarantees it only creates one per `OpenWallet`.

## KNOWN RISKS
- Event type names, payload field names beyond REQ-073, failure code list and reference rules for BET/LOSS are my interpretation; adjust before T04/T07 freeze contracts.
- `Money.UnmarshalJSON` rejects negatives by design; reconciliation differences (signed) must be serialized by the HTTP layer (Marshal works, Unmarshal does not).
- `Process` copies `Wallet`/`WagerTransaction` by value internally; callers must not share them across goroutines (aggregates are not thread-safe; the DB lock serializes them).
- `Envelope[T]` uses generics (Go ≥1.18); decoding an outbox payload into a typed envelope is the consumer's job.
