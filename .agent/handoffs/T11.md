IMPLEMENTED
- `internal/workers/outbox` Publisher: claims due rows with the existing `pg.Store.ClaimOutbox` (FOR UPDATE SKIP LOCKED + lease), sends each stored envelope through an injected `Sender`, then `MarkPublished` (REQ-068, REQ-069). Nothing is visible to it before SQL commit, so publication happens only after commit.
- Stable identity: `Message{EventID, EventType, Body, MessageGroupID=aggregateId, MessageDeduplicationID=eventId}` (D15). Body is the stored jsonb snapshot exactly as returned by PostgreSQL, identical on every publication; the envelope carries eventId, eventType, aggregateId, correlationId, optional causationId, occurredAt, version and data (REQ-072, from T03). A crash before or after the broker accepted the message is recovered by lease expiry and republishes the same eventId (REQ-069).
- Lease recovery and contention: two or more publishers never hold the same row (SKIP LOCKED). An abandoned claim is reclaimed after `Lease`. Acknowledgement (`MarkPublished`/`RetryOutbox`) only works for the current live lease owner; a stale owner gets `ErrConcurrentUpdate`, reported as `ResultLeaseLost`.
- Backoff: a failed send calls `RetryOutbox` with `Backoff.Delay(attemptCount+1)` (1s base, 5m cap, doubling; configurable); `last_error` stores the error text truncated to 500 bytes, never the payload. Events are never abandoned.
- Ordering within a batch: events of one aggregate are sent sequentially in outbox order; after a failure the rest of that aggregate in the batch are skipped (they keep their lease). Different aggregates run in parallel (`Concurrency`).
- Lease budget: before each send the publisher checks that `SendTimeout+AckTimeout` still fits inside the claim's lease; otherwise the event is skipped and left for the next claim. Config requires `SendTimeout+AckTimeout < Lease`.
- Metrics hooks: optional `Observer{Claimed(n), Attempted(Attempt)}`; Attempt carries Result (PUBLISHED, RETRY, LEASE_LOST, SKIPPED, ERROR), EventType, prior failed attempts, Lag (occurredAt -> confirmed publish = outbox delay), Duration, Err.
- Shutdown (REQ-003, REQ-008): every I/O takes a context. `Stop(ctx)` stops claiming and new sends, waits for the event in flight, and cancels it if the Fx stop deadline passes (row stays leased, republished later with the same eventId). `Start/Stop` idempotent. Fx `Module` provides `Config` (OUTBOX_* env vars), builds `Publisher`, binds start/stop to the lifecycle.
- REQ-070 (destination provisioning/routing docs) is T12/T18; this task consumes `EVENT_QUEUE_URL` only through the Sender the Lead will wire.

DECISIONS / ASSUMPTIONS
- The interface is named `outbox.Sender` (not Publisher, which is the worker type): `Send(ctx, Message) error`, returning only after the broker accepted the message. No SQS client or AWS dependency in this package.
- SQL is unchanged except that ClaimOutbox now also returns `seq` (`ClaimedEvent.Seq`). `UPDATE ... RETURNING` does not keep the claim query's ORDER BY, so the publisher sorts each claimed batch by Seq (stable) before grouping by aggregate. MarkPublished and RetryOutbox are reused as they are. The claim returns only event_id, payload and attempt_count, so aggregateId/eventType/occurredAt are read from the envelope header and checked against the row; a mismatch is reported as ERROR and never sent.
- Defaults (configurable, OUTBOX_*): batch 20, concurrency 4, lease 30s, send timeout 10s, ack timeout 5s, poll 500ms, backoff 1s..5m.
- Skipped events (earlier event of the aggregate failed, lease budget, shutdown) keep their lease until it expires rather than being rescheduled, so attempt_count is not inflated; delay is at most `Lease`.
KNOWN RISKS
- Delivery is at-least-once: a crash after the broker accepted and before the row is marked, or a lease that expires during a slow send, republishes the event. FIFO MessageDeduplicationID=eventId only suppresses duplicates inside SQS's 5 minute window; consumers must deduplicate by eventId (D11).
- Ordering per wallet is best-effort: within one batch it is kept, but across instances or after a backed-off failure a later event of the same wallet can be published by another instance before the earlier one retries. No guarantee depends on it (D15).
- A row whose stored payload is malformed is never sent and is retried forever at lease-expiry granularity (logged at error level). There is no dead-letter/failed state in the schema.
- A failing event is retried at the 5 minute cap indefinitely; alerting must use the Observer/metric on outbox lag and RETRY counts (T13).
- Lease timing uses DB `now()` for the claim and the app clock for the budget; skew shifts the budget check by the skew. The budget is computed from a timestamp taken before the claim, so it errs on the safe side.
