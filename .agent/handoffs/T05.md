IMPLEMENTED:
- `internal/auth` (stdlib-only; no `go.mod`/`go.sum` change): OIDC bearer-token verifier with lazy JWKS/discovery fetch, RS256 and ES256 only, strict claim checks, and HTTP middleware.
- Verification: compact JWT only (<=16 KiB); alg allow-list (`none`/HS* rejected before key lookup); `kid` required; `crit` rejected; key type must match alg; RSA keys < 2048 bits and non-`sig` keys ignored; `iss` exact match; `aud` (string or array) must contain the configured audience; `exp` required (numeric, quoted strings rejected), `nbf` honored; `sub` required; configurable `ClockSkew` (default 0).
- JWKS cache: single-flight refresh that outlives a single caller but honors each caller's context (REQ-008); 10 min TTL; 10 s refresh cooldown so random `kid`s cannot amplify fetches; stale keys keep verifying when the IdP is down; unknown `kid` with unreachable IdP fails closed as `ErrKeysUnavailable` (HTTP 503). Discovery checks that the discovered `issuer` equals the configured one.
- Claim mapping: provider = string claim `provider_id` (opaque ID rules as in contract: non-empty, <=255 bytes, no control chars/surrounding space; malformed claim rejects the token). Scopes come from `scope` (space separated), `scp`, `roles` and `realm_access.roles`. Malformed scope claims reject the token.
- Internal scopes: `wagering:provider` (business endpoints; also needs `provider_id`) and `wagering:internal` (wallet, ledger, reconciliation). `Identity.IsProvider()` = scope + claim; `IsInternal()` = internal scope.
- Middleware (`*auth.Middleware`): `Authenticate`, `RequireProvider`, `RequireInternal`, and combined `Provider` / `Internal`. 401 (+`WWW-Authenticate`) for absent/invalid/expired; 503 (+`Retry-After`) for unavailable keys or cancelled context; 403 for wrong scope. Bodies use `contract.ErrorBody` with codes `UNAUTHENTICATED`, `FORBIDDEN`, `TEMPORARILY_UNAVAILABLE`; reasons are logged (never the token) and not returned. Rejected requests never reach the wrapped handler.
- Provider isolation helpers: `auth.AuthorizeProvider(ctx, providerID)` (returns `ErrProviderMismatch` for another provider, `ErrForbidden` for a non-provider principal), `auth.ProviderScope(ctx)`, `auth.FromContext`, `Middleware.WriteError` (renders those errors as 403).
- Fx: `auth.Module` provides `Options` (from `config.Config`), `*Verifier` (also as `TokenVerifier`) and `*Middleware`.

DECISIONS / ASSUMPTIONS:
- Stdlib-only JWT verification was chosen to avoid `go.mod` churn across parallel worktrees; only RS256/ES256 are supported (Keycloak default is RS256).
- Claim contract (Lead was informed; coordinator asked for `provider_id` plus internal role/scope): `provider_id` claim; scopes/roles named exactly `wagering:provider` and `wagering:internal`. The realm (R12) must emit them, e.g. a hardcoded/attribute `provider_id` mapper per provider client, client scopes `wagering:provider` / `wagering:internal`, and an audience mapper for `OIDC_AUDIENCE`. The same name may arrive as a realm role.
- Optional env overrides read in `auth.OptionsFromConfig`: `OIDC_JWKS_URL` (skips discovery; needed when the app reaches Keycloak at `keycloak:8080` but tokens carry `http://localhost:8082/realms/wagering`) and `OIDC_PROVIDER_CLAIM`. `internal/config` was not edited (not owned by T05).
- Expiry has zero leeway by default so "expired credentials fail" is exact; `Options.ClockSkew` exists if needed.
- A token with both scopes is not rejected; realm configuration must keep provider and internal clients separate.
