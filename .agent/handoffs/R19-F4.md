# R19-F4 — HTTP transient database errors

## Change

- Added `pg.IsTransient` for PostgreSQL connection and pool acquisition failures, network errors, SQLSTATE `08*`, `57P0*`, `40001`, `40P01`, and concurrent update failures. Constraint and other SQL failures remain nontransient.
- HTTP maps those failures, plus existing typed transient errors and request cancellation, to `503` with `TEMPORARILY_UNAVAILABLE`, a generic message, and `Retry-After: 5`. Existing validation, business rejection, conflict, missing resource, and permanent failure responses retain their statuses. Database details are excluded from the response.
- Added focused classifier and HTTP response tests, including an actual request through a closed pgx pool.
