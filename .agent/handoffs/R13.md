# R13 IDP Repair

## What was done
1. **Compose Configuration (`compose.yaml`)**:
   - Configured the App to use `http://localhost:8082/realms/wagering` as the expected `OIDC_ISSUER_URL` since external testing scripts fetch tokens via localhost mapping.
   - Set `OIDC_JWKS_URL=http://keycloak:8080/realms/wagering/protocol/openid-connect/certs` to allow the App container to bypass discovery and directly reach the Keycloak container over the Docker bridge network to fetch keys.

2. **Realm Mappings (`infra/keycloak/realm-export.json`)**:
   - Validated that the `provider_id` mapper was correctly set on the clients. (Note: The previous live container was caching an older version of the configuration without it).
   - Added `roles` mappers to inject `wagering:provider` scope for the `provider-a` and `provider-b` clients.
   - Added `roles` mapper to inject `wagering:internal` scope for the `internal-service` client.
   - Added `audience-mapper` to all three clients to properly inject the `account` audience required by the verifier middleware.

3. **SQS Policy (`infra/localstack/init-sqs.sh`)**:
   - Refactored the policy creation into a `generate_policy` function that accepts the queue name as a parameter, ensuring the `Resource` ARN exactly matches the queue URL it's attached to (e.g., `wager-events.fifo` vs `wager-transactions.fifo`).
